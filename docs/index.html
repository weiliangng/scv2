Introduction

SCV2 is an STM32-based controller for a robot supercapacitor bank. In normal external control it uses fresh referee-UART information first, then CAN commands; it continuously enforces voltage, fault, and timing protection before enabling the power stage.

Purpose

Help a robot team integrate and operate a supercapacitor controller with clear visibility into control decisions, energy state, and electrical telemetry.

Competition-facing control

Reads the referee stream for chassis power and buffer energy, with CAN available as the alternate external command path.

Diagnosable by design

USB CLI, an always-on UART telemetry stream, CAN telemetry, and a desktop dashboard make faults and stale inputs easier to isolate.

Physical installation for competition

Use this as the final on-robot checklist. The repository does not define a mechanical mounting drawing or a board-connector pinout, so confirm those details against your released hardware documentation before powering the system.

Mount and protect

Secure the controller and bank so that vibration cannot loosen fasteners or strain cables. Keep conductive debris, tools, and exposed terminals clear of the power path.

Inspect the power path

Before energising, verify polarity, connector seating, insulation, and the team-approved fuse, switch, and shutdown arrangement.

Connect the control links

Connect the agreed referee-UART and/or CAN interfaces, including their required common reference. Check wiring against the robot schematic—not this trial site.

Commission safely

Start in an approved current-limited setup. Observe the controller before enabling the power stage and record the final competition configuration.

Safety note: a software ok response confirms command acceptance, not a physical output change. Verify the actual state and follow your team’s electrical safety procedure.

Interfacing with the robot

External mode prioritises a fresh, CRC-validated referee UART power-and-energy pair. If that is not available, the controller uses fresh CAN input. If neither source is fresh, it stays in a no-source state rather than enabling the stage.

Referee UART

The board receives referee data on USART3 at 115200 baud, 8-N-1. Both power and energy must be fresh for the UART control path to request switch enable.

CAN command and telemetry

CAN is the alternate command source and also carries compact downstream telemetry: classic CAN, standard ID 0x077, 1 Mbit/s, 8-byte frames.

Telemetry UART

USART1 transmits a T1 CSV record every 10 ms at 921600 baud, 8-N-1 for a receiver, bridge, or test PC.

Debugging features

How to assess bank capacity

Use the health fields in T1 during a controlled test: cap_energy_mJ, cap_dE_mJ_min, cap_dV_mV_min, and the derate counters expose the controller’s one-minute health windows. A formal capacity measurement still needs a team-approved load profile, voltage limits, and independent instrumentation.

FAQ

Why is switch enable off even though a command was accepted?

Check status or the dashboard for fault state, undervoltage lockout, stale command sources, converter direction, capacitor-voltage lockout, and the minimum on/off timers. Acceptance alone does not override these protections.

Can the dashboard and CLI use the same USB port together?

No. A serial port is normally owned by one program at a time. Close the dashboard before opening a CLI terminal, and close the terminal before reconnecting the dashboard.

Which page should I use for hardware pinouts?

This trial site deliberately does not invent a board pinout. Use your released schematic, connector documentation, and competition wiring record; then link them here when they are ready for publication.
